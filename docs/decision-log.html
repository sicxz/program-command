2026-08-11 Solo-maintainer delivery: zero approvals with gated autonomous merge
Chose
Keep pull requests and strict required checks on main, require review-thread resolution, and use zero required approving reviews while Travis is the only human maintainer. For approved issues and implementation-ready plans, AGENTS.md now grants standing authority to branch, test, commit, push, open a ready PR, repair in-scope CI or review findings, and squash-merge once the latest head is green, focused, reviewed, and reported mergeable by GitHub. Agents report milestones instead of handing routine clicks back to Travis.
Why
A one-review rule cannot provide independent review when agent work is authored through Travis's identity, so it adds an owner-bypass step without adding a second human. Required CI, focused PRs, review-thread resolution, the forbidden-path guard, and the manual production deploy remain the useful controls.
Rejected
Routine click-by-click supervision; restoring one required approval while Travis remains the sole human; and blanket merge authority that could bypass failed checks, unresolved feedback, forbidden paths, or production controls.
Evidence
Live ruleset audit on 2026-08-11: protect-main (ruleset 13362450, last updated 2026-07-21) already required zero approvals and retained strict test, onboarding, and guard-forbidden-paths checks. protect-develop (ruleset 13362496) also required zero approvals. No live ruleset write was needed or performed for this decision.

2026-05-21 Branch protection: 1 required review with repo-admin bypass
Chose
Set the protect-main ruleset to require 1 approving review and added the repo-admin role as the sole bypass actor; also enabled auto-delete of merged head branches. No-force-push, no-deletion, PR-required, and strict test+onboarding checks were already live.
Why
Forces human eyes on agent-authored PRs before merge while keeping the solo maintainer able to land their own hotfixes (GitHub blocks self-approval, so the admin bypass prevents lockout). Agents are non-admin and stay fully bound.
Rejected
0 reviews (no human gate on agent work); 1 review with no bypass (would lock the solo maintainer out of their own PRs).
Note
Protection is enforced via repository rulesets, not classic branch protection — the classic branches/main/protection API returns 404 by design.
2026-05-21 Keep the Node API surface; rehost the Sheets export (do not cut)
Chose
Keep api-server.js / google-sheets-client.js / POST /api/export-to-sheets as a local/dev-only tool; document it as not-in-prod; open a follow-up to rehost the export so it works against the static Pages surface.

The Sheets export is a real, needed function for faculty workloads (and a desirable backup/institutional archive path for schedules). Cutting it would delete a wanted capability; it is just mis-hosted for a static-Pages world.

2026-05-19 Editor allowlist mutable only via direct SQL
Chose
Four rows in public.editors; no UI, no API, no self-service add/remove.
Why
The allowlist is the only thing standing between an authenticated user and write access to prod data; a UI surface would be a new attack/mistake vector for a control with four total entries.
Rejected
Admin UI for editor management — explicitly out of scope until editor count or churn justifies the complexity.
2026-05-19 Email signups disabled at Supabase project level
Chose
Toggle off in the Supabase dashboard; verified by probe returning 422 signup_disabled.
Why
The editor allowlist is the only write gate. Open signup would let any address create an auth.users row — harmless on its own, but a future bug that grants editor-by-default would instantly become exploitable.
Rejected
Leave signups open and rely on the allowlist alone — defense in depth is cheap here.
2026-05-19 Manual workflow_dispatch deploy, gated on per-SHA CI
Chose
Remove push: branches: [main] trigger; deploy job's first step queries the deployed commit's test + onboarding check-runs and aborts unless both are success.
Why
Auto-deploy-on-push is the load-bearing risk for a solo maintainer supervising agents; a per-SHA gate also prevents a later un-CI'd commit from riding a stale green.
Rejected
"Most recent CI run" gate — defeated by a second commit landing between PR merge and dispatch.
