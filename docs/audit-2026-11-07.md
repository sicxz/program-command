## Summary

1. The schedule never shows the database's course titles. Two hardcoded override maps
   win, then the generated catalog, and the Supabase `courses.title` is only a fallback.
   Renaming a course in Course Management therefore changes nothing visible. That is why
   DESN 374 could not be fixed from the app.
2. "Applied Design" for DESN 374 was Travis's own decision on 2026-09-15 (issue #311),
   shipped in #316. Banner has titled the course "APPLIED AI" since the Sep 22 capture,
   and the Supabase row already reads "Applied AI" (hand-edited). The repo pins
   "Applied Design" in seven places.
3. The Supabase `courses` table carries wrong titles for 30 of the 31 DESN courses that
   appear in the 2025-26 and 2026-27 schedules, and DESN 490 carries 2 credits instead
   of 5. The Courses page displays these rows raw. The schedule pages mask them.
4. The AY 2026-27 schedule now matches Banner on every Fall 2026 instructor and slot.
   Winter and Spring 2027 differ from the Sep 17 captures on 11 sections.
5. Live site health is good: 24 pages, 81 local assets, all 200; no console errors on
   the two public pages; 76 suites / 561 tests pass.
6. Docs drift: ORIENT's next action is done; ONBOARDING states 1 required review (it is

## 1. How a course title is chosen (root cause)

Program Command, `program-command.html`:

- `COURSE_TITLE_OVERRIDES` (:5838-5890), 52 hardcoded code-to-title pairs.
- `getCanonicalCourseTitleByCode` (:8637-8645): override, then `courseCatalogByCode`,
  then the fallback passed in. The fallback is the database title.
- `normalizeScheduleCourseCodes` (:8655-8676) rewrites every loaded course's `name`
  with that canonical title after `loadScheduleDataFromDatabase` (:14329) has fetched
  `course:courses(code, title, default_credits)` (:14380). The database title is read
  and then discarded.
- `ensureCourseCatalogLoaded` (:13623-13692) fills `courseCatalogByCode` from
  `ewu-design-catalog/courses/courses-202526.md` first (the 2025-26 catalog text, which
  still says "AI + DESIGN"), and from `data/course-catalog.json` only if the markdown
  fetch fails. The overrides hide this third source.
- `syncCourseCatalogTitlesToSupabase` (:13694-13714) would push catalog titles into
  Supabase. It has no caller (one grep hit, its own definition). Dead code; hand edits
  in Course Management are not reverted by the app.
- The legacy `scheduleData` seed (:7404-7510) is a hardcoded 2025-26 schedule with
  old rooms and the "Applied Design" name (:7426, :7470, :7494). It is the initial
  state before the database or localStorage load replaces it.

Public schedule, `pages/public-schedule.js`: a second copy of the same 52-row
`COURSE_TITLE_OVERRIDES` (:118-171) and the same precedence in
`getCanonicalCourseTitleByCode` (:270-278). The two copies are identical today; nothing
enforces that.

Tests pin the behavior: `tests/public-schedule.test.js:104-135` ("uses canonical course
titles instead of stale Supabase titles"), `:138-140` (DESN 374 must read "Applied
Design"), and `tests/course-titles.test.js:44-57`.

Course Management, `pages/course-management.js`: `renderCatalogTable` (:88-150) prints
`course.title` straight from `dbService.getCourses()` (`js/db-service.js:100-113`), and
`handleCourseSubmit` (:420-477) saves the edited title with `dbService.updateCourse`.
The page edits the one source the schedule ignores. The page is reachable from
Archived features (`program-command.html:5524`).

Consequences:

- The Courses page (`pages/course-management.html`) shows this table as is. That is
  the "courses aren't correct" report.
- Program Command hydrates credits from the database
  (`js/schedule-data-utils.js:188`, `record.course.default_credits`), so DESN 490
  counts as 2 credits in the editing app's load math while the public page shows
  5 credits from the catalog (`pages/public-schedule.js:280-286`).
- `scripts/supabase-sync-course-catalog.sql` is the only repair script, and it is stale:
  it would set 368/378/468 to "Code + Design 1/2/3" and 374 to "AI + Design". It is a
  `*.sql` file, so the forbidden-path guard blocks agents from editing it
  (`scripts/check-forbidden-paths.cjs`).

Course Management level control. The edit form's `courseLevel` select offers
`intro`, `intermediate`, `advanced`, `graduate` (`pages/course-management.html:393-398`),
and `levelFilter` offers the same (:258-264). Every repo source writes numeric levels:
`scripts/migrate-to-supabase.js:170` copies `course.level` from the catalog (`"100"` to
`"400"`), and `scripts/supabase-sync-course-catalog.sql` sets `'300'` etc. When
`editCourse` (:358-383) assigns a numeric level to that select, the select has no
matching option and its value becomes empty, and `handleCourseSubmit` (:434) saves
that empty string through `updateCourse`, which always writes `level`
(`js/db-service.js:171`). The level filter cannot match numeric values. Not verified
against the live rows (anon cannot read the table); one `SELECT code, level FROM
courses` settles it.
